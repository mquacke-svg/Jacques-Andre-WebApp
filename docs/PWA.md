# Мобильное приложение «Жак-Андрэ»


## Запуск

Приложение находится в `/app` рядом с обычным сайтом. PHP 8.3 и расширения проверяются командой `php scripts/check-env.php`. Выполнить `php scripts/setup.php` перед первым запуском: исходный `data/catalog.sqlite` копируется в закрытую `.local/bakery.sqlite` только при отсутствии рабочей базы. Существующую базу команда не заменяет.

Установить `APP_URL` в точный HTTPS-адрес сайта. При размещении на Beget использовать текущие `DATABASE_PATH`, `UPLOADS_PATH`, `SESSION_PATH`, `BACKUP_PATH` за пределами веб-корня; не копировать локальную базу поверх действующей. Веб-корень — только `public/`. В Apache требуется mod_rewrite и поставляемый `.htaccess`, включая правило для `/app` (внутри public есть одноимённый каталог ресурсов).

Если PECL scrypt отсутствует, допускается явно настроить абсолютный `SCRYPT_PYTHON_BINARY` на Python 3 с `hashlib.scrypt`. Адаптер сохраняет формат прежних паролей и использует локальный subprocess со stdin без shell. Проверить `php scripts/check-env.php` и `php tests/password-test.php` с этой переменной; неподходящий обработчик приводит к отказу авторизации, без смены алгоритма или формата.

Локально: `php -S 127.0.0.1:3083 -t public router.php`, затем открыть `http://127.0.0.1:3083/app`.

## Первый сотрудник

Аккаунтов в исходной базе нет. Команда `php scripts/create-admin.php` читает JSON из стандартного ввода с полями `login` и `password`. Пароль — 12–128 символов; существующий пользователь не перезаписывается. Передавать JSON из защищённого менеджера секретов или через stdin, без пароля в аргументах процесса, истории команд и файлах репозитория. Вход сотрудника: `/login?admin=1`. Публичных стандартных учётных данных нет.

## Поведение

Каталог, корзина, регистрация, сессии, остатки и заказы общие с сайтом. Заказ без регистрации доступен своему браузеру по гостевой cookie; после входа гостевые заказы можно сохранить в кабинете. Сотрудник принимает и меняет статусы в существующей админке. Уведомления сотруднику во внешних сервисах не отправляются: заказы проверяются в админке.

Самовывоз и доставка используют настройки базы. Товар без цены и вариантов отображается с текстом «Цена уточняется» и недоступен для заказа. Заказы приложения сохраняются как настоящие заявки со статусом `pending`, оплата при получении. Перед открытием продаж проверить актуальность ассортимента, цен и контактов пекарен.

## Установка и сеть

Android: открыть `/app` в поддерживаемом браузере и выбрать установку. iPhone: Safari → «Поделиться» → «На экран Домой». Нативная кнопка установки показывается, когда браузер предоставляет соответствующее событие. Manifest запускает `/app/` в standalone, scope `/app/`.

Service worker кэширует только разрешённые публичные ресурсы. Персональные HTML-страницы, CSRF, аккаунты, корзины, загруженные файлы и заказы не кэшируются. Без сети показывается нейтральный экран; отправка заказа офлайн и очередь повторной отправки отсутствуют. Изменение ресурсов service worker требует новой версии имени кэша.

## Проверки и выпуск

`php tests/auth-test.php`, `php tests/shop-test.php`, `php tests/backup-test.php`, `node tests/pwa-worker.cjs`, `node tests/admin-cli.cjs`, `node tests/browser.cjs`, `node tests/mobile.cjs`. Для браузерных проверок требуется установленный Edge, `npm ci --ignore-scripts` и `PHP_BINARY`, указывающий на PHP. Сценарии используют отдельную тестовую базу; браузерные наборы запускать последовательно.

Перед выпуском проверить синтаксис PHP, мобильные/настольные скриншоты, HTTPS, manifest, регистрацию worker и установку на физических устройствах Android/iPhone. Эмуляция размеров окна не заменяет проверку установки на устройствах.

Выпускать код отдельным релизом по инструкции хостинга, предварительно сохранив актуальные SQLite и uploads. Конфигурацию, базу, загрузки и сессии при обновлении кода не заменять. Откат кода выполняется с текущими данными, а не восстановлением старой базы поверх новых заказов.
